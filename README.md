# os2026lx

面向本校《操作系统》课程的实验指导作品，参赛方向为操作系统实验教程与竞赛指导。

> **当前状态：第一版完成阶段。** 本地验证并完成了lab1（4个子目）和lab2的实验包设计
> 本版本针对 Mac 设备进行了兼容，有对应的 Mac 适配的实验包（用 Windows 打开会有标红的，需要用 Mac）
> 仓库中的内容会随确认结果调整，在提交日期 12.12 及以后后为初赛的终稿

## 项目目标

基于本校《操作系统》课程已有的实验要求（进程管理、内存管理），
重新设计并实现一套可以独立使用的实验资源：

- **题目文档** —— 原理、任务说明、分步实现指导、常见错误排查
- **起点代码** —— 学生拿到就能编译运行的框架，关键处留待实现
- **测例** —— 自动判定，失败时给出可读的错误信息
- **参考实现** —— 卡住时可对照的完整答案
- **兼容性** —— 使用 Windows（包含虚拟机方案）以及 Mac 设备都受支持。其中，因为 Mac 设备有一些函数/功能的调用和 Windows 不一样，故特别对 Mac 版本做了适配性修改，带有 `XXXforMacOS`的实验包即为 Mac 设备使用。
- **其它** —— 答案文件夹的 3.c 4.c 9.c 这样的文件不直接参与学生（读者）编写，它们的命名源自学校的实验文档里面所涉及平台的代码文件名，因为早期设计的时候为了对齐文档而如此命名并一直沿用。

## 原创性和AI使用

本实验项目设计和编写过程中使用了AI辅助（Deepseek V4.1 flash，GLM 5.1），Claude（主要接入上述模型，未使用 Claude官方模型）主要用途是

- 辅助我们完成技术细节确认（需要哪些前置安装的的内容，这份实验包在其他设备上跑会有哪些常见问题等）
- 纠正设计用例时的错误（比如初版设计时将 main 和面向学生（读者）侧的impl.c写在了一起，后来将他们拆开，这样impl.c更简洁，同时去掉不需要让学生（读者）看到的内容。）关键写法：先写出主要的 -> AI纠错 -> 拆开成给学生（读者）的TODO
- 在不同的平台上检查兼容性，因为学校学生有些用的是苹果电脑，所以lab1和lab2都需要针对Mac设备单独适配好，由AI查出一些函数/功能在 Windows 和 Mac 之间有不同的实现写法（比如lab1里面的两个）AI提出的解决方案是直接用Mac的写法，但是我们考虑到一致性问题，决定用映射的方式去解决（也就是两个写法都可以）
- 反作弊部分的实现思路评判（这部分在初期讨论设计时没有考虑到，是整体确定之后才考虑加上的，属于锦上添花的部分）

- 文档一致性核对，因为每部分完成过程中，对应代码文件的文件层级发生过很多次变化，放入最终实验包时，由AI核对了出现错误的文件层级不一致问题（这会导致误读发生）。
- 我们先完全写出少量用MD写法的文档，AI用MD的写法将标为重要的部分加*号加粗等，并解决文档排版问题（主要是代码框部分和标注，```bash这种）以及表格的创建。

- 快速验证：在不同的设备上验证，采用“我们以学生（读者）的视角补全+验证，AI以相同视角同步检查环境+沙箱里面跑一遍”的思路，AI会发现很多潜在的隐患，我们根据这些上报做决策。
